# ADR 0003: 결제 시스템 통합

## 상태
승인됨 (2024-01)

## 컨텍스트
구인자가 일자리 등록 시 예치금을 결제하고, 근무 완료 후 구직자에게 정산하는 시스템이 필요합니다.

### 요구사항
- 신용카드, 계좌이체 지원
- 에스크로 방식 (예치 → 정산)
- 수수료 처리
- 환불 처리

## 결정

### 토스페이먼츠 API 채택

**이유:**
- 국내 PG 중 개발자 경험 최고
- 명확한 API 문서
- 테스트 환경 제공
- 합리적인 수수료 (카드 2.5~3.5%)

### 결제 흐름

```
┌─────────────────────────────────────────────────────────┐
│                    결제 흐름                             │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. [구인자] 일자리 등록                                 │
│       ↓                                                 │
│  2. [앱] 토스페이먼츠 SDK 결제창 호출                    │
│       ↓                                                 │
│  3. [토스] 결제 승인 → paymentKey 반환                  │
│       ↓                                                 │
│  4. [Backend] confirmPayment API 호출                   │
│       ↓                                                 │
│  5. [DB] Payment 레코드 생성 (status: ESCROW)           │
│       ↓                                                 │
│  6. [근무 완료] 구인자 승인                              │
│       ↓                                                 │
│  7. [Backend] 정산 처리                                 │
│       - 플랫폼 수수료 차감                               │
│       - 구직자 계좌 입금 (별도 정산 시스템)              │
│       ↓                                                 │
│  8. [DB] Payment status: COMPLETED                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 환불 정책
- 매칭 전 취소: 전액 환불
- 매칭 후 구인자 취소: 위약금 20% 차감 후 환불
- 매칭 후 구직자 노쇼: 전액 반환

## 대안 검토

### 아임포트 (포트원)
- 여러 PG 통합 가능하나 복잡도 증가

### 카카오페이 단독
- 사용자층 제한

## 결과

### 구현 상세
```typescript
// Payment Entity 상태
enum PaymentStatus {
  PENDING = 'pending',      // 결제 대기
  ESCROW = 'escrow',        // 예치 완료
  COMPLETED = 'completed',  // 정산 완료
  REFUNDED = 'refunded',    // 환불됨
  FAILED = 'failed',        // 실패
}

// 수수료 구조
const PLATFORM_FEE_RATE = 0.1; // 10%
```

### 보안 고려사항
- Secret Key는 환경변수로만 관리
- Webhook signature 검증 필수
- 금액 위변조 방지 (서버에서 재계산)
